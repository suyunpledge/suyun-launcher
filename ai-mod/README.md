# SuyunCraft AI 0.5.0

用于 **Minecraft Java 1.21.1 + Fabric + Java 21** 的客户端 AI 动作模组，配套 SuyunCraft 1.8 安装入口。桥接服务使用 Python 3.10+ 标准库，不需要 pip 安装依赖。

## 0.5.0：指令输入与战斗控制

两个新能力都默认关闭，需要在游戏目录 `config/suyuncraft-ai.json` 显式开启：

```json
"allowCommands": true,
"allowCombat": true
```

**指令输入（allowCommands）**：新动作 `{"type":"command","command":"time set day"}` 让 AI 发送一条白名单内的原版命令。白名单根命令固定为 `time / weather / gamemode / difficulty / tp / effect`（模组和桥接两侧同时校验），命令体 1–100 字符、仅限 `[A-Za-z0-9_-.:@ ]`、最多 8 个参数、不允许前导斜杠和聊天内容。模组通过 `sendCommand` 发送，不发送聊天消息。命令在世界开启作弊（单人默认有权限）时才会生效；执行前仍会二次校验白名单，不合法即拒绝。桥接新增本地零 API 命令「调成白天」「停止下雨」。

**战斗控制（allowCombat）**：新动作 `{"type":"attack","ticks":1-100,"target":"nearest" 可选,"approach":true 可选}`：

- `target:"nearest"` 锁定 8 格内最近敌对生物，每 tick 平滑追踪瞄准（复用 0.4 的限速转头），攻击冷却恢复即挥击；目标被击败自动转向下一个，全部清除后播报结束。省略 target 时攻击准星处的敌对生物（可先用 `lookat` 瞄准）。
- `approach:true` 在距离大于 3.5 格时自动接近（含 1 格台阶自动跳）。
- 安全边界：仅攻击敌对生物（HostileEntity），不会攻击玩家/村民/动物；玩家生命 <10、目标逃离超过 12 格、打开界面即停止。全局队列原有的生命 <6、切世界等停止条件不变。
- `/scai fight [1-200]`（默认 100）：本地零 API 战斗，锁定最近敌对生物并追击。
- 环境摘要新增 `nearestHostileType` / `nearestHostileDistance`（8 格内最近敌对生物类型与距离），模型可据此决定战斗或撤退；两个新状态门 `commandsAllowed` / `combatAllowed` 随每次请求上报。

验证：新增 19 项命令白名单检查（根白名单、字符集、注入拒止）、桥接增至 27 项（command/attack 校验、本地零 API 命令、状态门与环境透传）；116 蓝图、14 对话、19 运动、202 启动器回归与 16 项界面检查全部通过。**尚未进入真实 Minecraft 验证战斗手感与指令权限路径。**

## 0.4.0：平滑动作、边走边转与本地行走

重点重做了人物动作的流畅度，动作协议向后兼容（新增字段均为可选）：

- **平滑转向**：`look` 不再瞬间甩头，改为每 tick 限速插值（yaw 18°/tick、pitch 12°/tick，最短路径跨 ±180°），且转向会自然延续到后续动作——“转身→前进”现在是一个连续动作而不是两次跳变。瞄准生命周期上限 100 tick，任务停止即释放。
- **move 增强**：可选 `yaw`（行走中平滑转向，边走边转头）、可选 `sprint:true`（仅 forward，按住疾跑键）；行走遇到 1 格台阶自动跳上，不再一碰就停；跳跃后 10 tick 内的短暂离地和下坡（4 格内有安全落脚）不会误判急停；连续受阻 8 tick 才停止并提示。
- **新动作 `lookat`**：`{"type":"lookat","x":..,"y":..,"z":..}` 平滑看向 24 格内的方块坐标，配合 `break`/`use` 瞄准，不再需要模型猜角度。
- **`/scai goto <x> <z> [步数1-400]`**：本地零 API 行走。持续按前进并平滑转向目标，自动跳 1 格台阶；每 30 tick 检测一次卡住，持续受阻或进入危险自动停止并播报剩余距离。与队列任务互斥，`/scai stop` 取消。
- **建造瞄准平滑化**：蓝图放置前渐进转头对准支撑面（上限 14 tick），到达后再次验证支撑并放置，不再瞬移准星。
- **HUD/对话面板**新增步行进度（目标坐标、剩余 tick、剩余距离）。
- 桥接新增本地零 API 命令「向前走十步」「向前跑一段」；`bridge.py` 动作校验支持上述可选字段与 `lookat`，多余字段仍然整体拒绝。
- 挖掘、放置、蓝图确认、危险与服务器回包检查、API 冷却/配额等边界全部保持不变。

验证：模组编译/重映射、116 蓝图/回包、14 对话/输入、19 项新增运动学检查（转向限速、±180° 最短路径、yaw/pitch 约定、到位阈值）、24 项桥接测试通过；启动器回归在版本引用更新后重跑。**尚未进入真实 Minecraft 验证平滑度手感与 goto 实际步行表现。**

## 0.3.1：与其他模组共用客户端

只释放 AI 占用的移动键，只取消 AI 开始的挖掘；空闲/打开面板/反复暂停不会再重置所有移动键或手动挖掘。AI 控制同一按键时仍可能与手动操作互相影响，接管前请停止任务。退出客户端时取消连接并关闭线程；网络最多一个运行任务和一个等待任务，避免快速取消/重发无限堆积。配置读取上限 64 KB。

`config/suyuncraft-ai.json` 可添加 `"showWorkHud": false` 隐藏 HUD，或用 `"hudX": 6, "hudY": 60` 避开小地图。坐标范围 0–8192，渲染时限制在窗口内；下一次提问或建造操作重读配置，无需额外请求。升级保留原配置，缺省为显示、左上角 6/6。

在启动器设置页重新点击「安装 AI 模组」更新，重启游戏生效。按 ID 备份改名的旧 AI JAR，保留第三方模组和现有 Fabric API；同名文件属于其他模组时拒绝覆盖。第三方模组通过「第三方模组管理」导入和停用，见项目 `MODS.md`。AI 本身仍限定 1.21.1 Fabric 和现有建造材料白名单。

编译/重映射、116 蓝图/回包、14 对话/输入、22 桥接、165 启动器回归、9 界面检查通过。未验证真实多模组游戏行为，未访问付费 API；冷却、每日次数和输出限制不变。

## 0.3：游戏内对话、计划和工作状态

在启动器设置页重新安装 AI 模组，重启游戏与桥接服务。输入 **`/scai` 或 `/scai chat`** 打开对话面板。

- **对话 / Enter**：讨论环境、建筑方案及任务状态，不执行动作。可先问“我想建一堵石墙，需要准备什么？”
- **交给AI执行 / Ctrl+Enter**：下达任务，可接着说“按刚才的方案做”。模型选择有界动作或蓝图；蓝图仍需确认，不会绕过原有材料和安全检查。
- **确认/继续**：确认蓝图或恢复任务并返回游戏。纯对话中输入“继续/确认”只给提示，不会直接放置方块；“停止/取消”可随时本地取消任务。
- **停止**：取消在途请求、动作队列和建造任务；已经发送到提供商的请求仍可能计费。
- **返回游戏 / Esc**：关闭面板。打开面板时本地动作暂挂，关闭后继续；游戏世界本身不会因这个面板暂停。
- **清空对话**：删除内存中的对话上下文并取消在途回复；保留已开始的本地动作/蓝图，需要取消工作请点停止。

面板显示用户消息、AI 回复、简短公开任务计划和本地执行事件。等待接口时显示“正在分析与规划”，回复后显示方案；这些是公开计划及实际状态，不是模型内部推理的实时转录。界面不读取或展示提供商的 `reasoning_content`。

返回游戏后，工作 HUD 显示请求状态、队列剩余和建造确认进度，不需要反复询问模型。HUD 随原版隐藏 HUD 的设置隐藏。已有任务未结束时可以继续对话，但不能再并发下达第二个工作任务；先停止当前任务再换任务。

面板最多保留 60 条事件，每条最多 600 字符。接口只携带最近 4 条用户/AI 消息，每条最多 160 字符，总计不超过 640 字符；状态日志和计划事件不作为历史重复上传。清空对话、断线或切换世界会清除上下文。没有自动后台聊天、自动追问、自动重新规划或无限任务循环；短历史可能不足以理解很久前的方案，需要时请重述。

接口增加 `mode=chat|work`、`history=[{role,content}]` 和可选 `plan=[...]`；旧请求默认 work。历史只允许 user/assistant 角色，计划最多 4 条、每条最多 60 字符；chat 模式在桥接和客户端两侧都禁止执行动作。工作状态以当前本地 `state.execution` 提供，AI 不应凭对话猜测完成情况。输入框单条消息上限仍为 300 字符，冷却、每日次数和输出令牌限制不变。

验证：模组编译/重映射及 116 项蓝图检查、11 项对话缓存检查通过；桥接 22 项测试、启动器 132 项回归和 5 项界面检查通过。对话模式的动作拒绝、历史角色/长度限制、实际 API 请求格式均用本地模拟测试。**尚未实际进入 Minecraft 检查面板布局、HUD、任务执行或连接付费模型**。

## 0.2：自动建造与环境判断

更新启动器后，在设置页重新点击「安装 AI 模组」。安装器将旧版带版本号的 AI JAR 移到游戏目录的 `suyuncraft-ai-backups`，新模组使用稳定文件名 `mods/suyuncraft-ai.jar`；原配置、令牌及每日限额文件保留。重启游戏与桥接服务后生效，不要在旧游戏进程运行时更换模组。

### 无需 AI 或桥接服务的本地命令

```text
/scai scan                              查看附近环境摘要
/scai goto <x> <z> [步数1-400]            平滑行走到目标坐标（0.4 起可用）
/scai fight [1-200]                     本地战斗：锁定最近敌对生物并追击（0.5 起可用，需 allowCombat）
/scai build floor3 minecraft:cobblestone  预览圆石平台
/scai confirm                           确认并自动放置
/scai status                            查看服务器确认数、已有数与剩余数
/scai resume                            调整站位或补材料后继续
/scai stop                              取消蓝图和其他动作
```

建造前需在实际游戏目录 `config/suyuncraft-ai.json` 设置 `allowWorldInteraction=true`。预览本身不放置方块；确认时重新读取开关。省略材料参数会使用当前手持物品；必须是受支持的建筑材料。材料放在快捷栏中，不会自动翻背包、生成物品或绕过服务器权限。

| 蓝图 | 几何与材料上限 |
| --- | --- |
| `floor3` | 面前 3×3 平台，脚部高度放置，9 块 |
| `wall3` | 前方两格处、宽 3 高 2 的墙，6 块 |
| `pillar3` | 前方两格处、高 3 的柱子，3 块 |
| `shelter3` | 3×3 地板、两格高围墙、屋顶，保留两格高门口及内部空间，32 块 |

支持圆石、石头、泥土、橡木板、玻璃、砖块、砂岩，对应 ID 为 `minecraft:cobblestone/stone/dirt/oak_planks/glass/bricks/sandstone`。蓝图固定在预览时的位置和四向朝向，玩家移动不会移动蓝图。目标位置必须为空气或相同材料，已有其他方块时拒绝覆盖，也不会自动拆除草、树木或建筑。

每次只发送一个放置操作，至少相隔 5 游戏刻，等待服务器 BlockUpdate/ChunkDelta 包确认目标材料后再计入成功；不会把客户端预测当作服务器确认。等待超过 60 游戏刻暂停，不自动重发。还会检查已加载区块、世界边界、高度、实体占位、支撑方块、视线、实际触及距离与附近危险；不通过箱子等方块实体作为点击支撑。已有相同材料单独计数。

建造不自动寻路。超出触及距离、视线被挡、没有支撑或材料不足时会暂停，移动到其他站位、补足材料或手动补支撑后用 `/scai resume` 继续；不会为了重新规划消耗 API。附近六格有可见客户端数据中的敌对生物、低血量、着火、打开界面或连续执行三分钟也会暂停；断线、切换世界会取消。部分服务器/反作弊规则可能拒绝动作，不能保证所有蓝图从一个站位完成。

### 环境与 AI 接口

`/scai scan` 在主线程做有界扫描：水平半径 3 格、垂直 -1 至 +2 格（196 个格子），统计未知区块、危险格、实心格、光照、降雨、八格内敌对生物以及快捷栏材料；并检查前后左右短距离移动是否有支撑、是否碰撞或接触危险。识别水/岩浆、火、岩浆块、仙人掌、浆果丛、细雪、篝火。未知区块按不安全处理，移动执行前还会重新判断。

这些是局部启发式观察，不包含完整地形语义，也不能保证识别所有模组危险。环境数据只在主动 ask 时随请求上传摘要，扫描和动作 tick 不会向模型发请求；不会上传逐块地图、截图、聊天或方块实体 NBT。

通过桥接输入 `/scai ask 观察环境`、`建造地板`、`建造平台`、`建造墙`、`建造柱子`、`建造小屋` 也走本地规则，零付费 API。更复杂的描述才调用模型。模型只能选预定义蓝图和材料，返回唯一的 `build` 动作，不能返回任意坐标、尺寸、脚本或夹带其他动作；仍先生成预览，需 `/scai confirm` 执行。桥接检查 `blueprints-v1` 能力标识，旧客户端不会收到无法执行的本地建造计划。

## 使用

1. 在启动器下载页安装 Minecraft **1.21.1 + Fabric**，回主页选中该版本。首次使用建议开启版本隔离、使用测试存档。
2. 设置页点击「安装 AI 模组」。安装器将模组、缺失的 Fabric API、随机本地令牌配置写入当前版本的实际游戏目录。已有 Fabric API 和配置会保留。
3. 点击「启动 AI 桥接」，在弹出的终端填写 API 的 **HTTPS 基础地址**（包括提供商要求的 `/v1` 或其他 API 路径）、模型 ID、API key。基础地址后会追加 `/chat/completions`。需选择支持 `messages` / `max_tokens` / 非流式 JSON 文本输出的兼容接口；不是所有厂商的原生接口都直接兼容。
4. 进入游戏使用 `/scai ask 向前走一步`，这是零 API 调用的本地动作。还支持本地「等待」「跳一下」。其他自然语言任务会发起一次规划请求。
5. `/scai stop` 停止动作、丢弃排队动作；`/scai status` 查看是否在请求和动作队列长度。

API key 仅保存在桥接终端进程的环境中，不写入模组、启动器 JSON、命令行参数或发布包。也可事先设置当前终端的 `SC_AI_BASE_URL`、`SC_AI_MODEL`、`SC_AI_API_KEY`，然后运行 `start-bridge.ps1 -ConfigPath <游戏目录/config/suyuncraft-ai.json>`。`SC_AI_PYTHON` 可指定 Python 可执行文件。脚本优先使用本机已存在的 Codex Python，其他机器回退到 PATH 中的 python。

桥接只绑定 `127.0.0.1:18765`，使用本地随机 Bearer token，拒绝带浏览器 Origin 的请求，不开放公网监听。一次只能服务一个正在规划的请求；不同隔离版本的配置令牌不同，切换版本时关闭旧桥接终端再启动新的。

## AI 可以做什么

- 转向：绝对 yaw / pitch。
- 小范围前后左右移动、跳跃，每个动作最多 100 游戏刻（正常约 5 秒）。
- 切换快捷栏 0–8 槽位。
- 等待。
- 对准近距离方块后持续挖掘或使用手持物品交互。**默认关闭**，需要修改实际游戏目录的 `config/suyuncraft-ai.json` 中 `allowWorldInteraction` 为 `true`；每次 ask 会重读配置。使用动作只触发一次交互。

当前控制现有玩家，提供上述有限蓝图；没有自动寻路、任意规模建筑、自动合成、实体攻击或任意游戏命令执行能力。模型无法执行系统命令，也没有聊天发送动作。客户端动作仍受服务器正常规则和权限约束。

打开界面、低血量、死亡、断线或切换世界会终止本地动作；暂停时释放按键并暂停执行，恢复后继续。碰到障碍或离地移动会停止。它尚不能完整识别悬崖、岩浆等危险，短距离动作也不能保证存档安全。鼠标和键盘仍属于当前玩家，执行时避免同时手动控制；需要随时用 `/scai stop` 结束。

## 如何省 API

| 策略 | 默认值 / 行为 |
| --- | --- |
| 按需调用 | 只有 `/scai ask` 自然语言任务才请求；空闲、tick 和游戏启动均不请求 |
| 本地简单任务 | 「向前走一步」「跳一下」「等待」零 API 调用 |
| 批量计划 | 单请求最多 8 个动作，本地队列执行；每步不会向模型汇报 |
| 上下文裁剪 | 单条任务最多 300 字；只发送位置、维度、血量、饥饿、朝向、手持物和瞄准方块，不发送聊天、截图或历史对话 |
| 输出上限 | `maxOutputTokens=384`，硬上限 512；没有自动续写 |
| 调用间隔 | 默认 10 秒，最短可设 2 秒；只限制远程 API，本地动作不扣额度 |
| 每日请求限额 | 默认 30 次，按 UTC 日期持久记录，重启不清零；每个配置目录独立计数 |
| 并发与失败 | 单次在途请求；超时、错误、非 JSON 回复均不自动重试、不自动重新规划 |
| 不缓存动作计划 | 避免把旧世界状态对应的动作重复执行；等待下一个明确任务 |

`cooldownSeconds`、`dailyRequests`、`maxOutputTokens` 也在上述 JSON 内，修改后需重启桥接。已发给提供商的请求不能靠 `/scai stop` 保证免计费；失败请求也占本地限额，以免超时重试重复扣费。预算文件为同目录 `suyuncraft-ai-quota.local.json`。模型内部推理、提供商定价和计费口径由厂商决定；请求次数限制不等于金额上限，建议同时设置提供商账户预算，选择小型非推理模型。

桥接不会为了修复格式错误再次调用 API；模型必须回复严格 JSON，不接受 Markdown 代码围栏。动作 schema 见 `bridge/bridge.py` 的 `SYSTEM` 和 `validate()`。如所选模型默认进行长推理，需按提供商文档在 `Planner.remote()` 增加对应关闭推理参数；当前没有硬编码任何厂商的私有参数。

## 构建、测试与启动器集成

```powershell
# 安装 JDK 21，设置 JAVA_HOME；源码包包含 Gradle wrapper
.\build-mod.ps1
# 测试不调用任何真实 API
python -m unittest discover -s bridge -v
```

`build-mod.ps1` 构建并将 Fabric API 从官方 Maven 下载，验证 SHA‑256，再把运行资源暂存到 `%APPDATA%/SuyunCraft/ai-mod`，因此桌面单文件启动器也能安装模组。构建输出在 `dist/`；`.tools/`（本机 JDK）、`.gradle/` 和 `build/` 不进入发布包。

首次构建需要网络下载 Gradle、Loom 和 Minecraft 开发依赖。Windows 中文用户目录可能导致 JDK AF_UNIX 临时套接字失败，脚本仅对当前构建进程使用 `%PUBLIC%/SuyunCraft-build-tmp` 作为 TEMP。若本机使用系统代理而 Gradle 未使用它，请通过 JAVA_TOOL_OPTIONS 设置对应的 http/https proxyHost、proxyPort，并为 localhost/127.* 设置 nonProxyHosts；不要把本机代理端口写死到仓库。

编译只引用实际使用的 3 个 Fabric API 模块。打包重映射时不下载各架构 LWJGL native 二进制（Java 类层次来自编译 classpath）；`runClient` 等运行任务仍保留正常 native 依赖。可选 `.tools/maven` 只是本机构建时从官方 Maven 下载并校验的缓存，不打包分发；干净环境仍通过标准 Maven 仓库解析依赖。

0.2 本轮验证：模组 Java 21 编译及发行 JAR 重映射成功；启动器 132 项离线回归、5 项 UI 检查、Python 桥接 17 项测试及 Java 蓝图/放置确认 116 项检查通过。Java 检查由 `check` 自动运行，覆盖几何、四向旋转、门口、内部空间、支撑连通性、拒绝/超时与仅服务器确认可算成功。API 请求格式使用模拟响应验证，没有调用付费接口，也没有实际进入游戏验证建造。应先在测试存档人工检查站位、放置回包、受保护区域和中断恢复。

启动器入口：`src/AiIntegration.cs`、`src/MainForm.Settings.cs`。安装使用原子写入、安全路径约束和实际隔离目录，不在启动器进程执行远程模型请求，不增加普通游戏启动时的网络开销。
