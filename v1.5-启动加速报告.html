Performance Report

启动加速：9.3 秒 → 0.88 秒

SuyunCraft v1.5 持久化校验缓存 · 实测数据来自本机 1.21.11（4,677 文件 / 528 MB）
日期 2026-10-23加速比 10.6×回归 131 离线 + 5 UI 全过兼容 .NET 4.8 / C# 5

问题与方案

每次点「启动游戏」，旧逻辑对全部文件做完整 SHA-1 校验，本机实测 9,338 ms——这是点击到游戏拉起之间最大的等待块。v1.5 引入持久化校验缓存（VerifyStore）：完整校验通过的文件记录「长度 + 修改时间 + 头 4KB 哈希」三元组，下次启动三元组未变即跳过全量哈希，只做 stat 与抽样。

场景耗时说明
旧版每次启动9,338 ms全量 SHA-1，4,600+ 文件
v1.5 首次启动（建缓存）836 ms含全量校验 + 写缓存（缓存文件未变时部分命中）
v1.5 日常启动881 ms缓存命中 + 大文件头部抽样
强制完整校验后≈9 s设置页一键触发，与旧版一致的安全强度

安全边界（分层防伪）

文件类别校验策略实测
>32 KB（客户端 jar、核心库、大资源，约 150 个）length + mtime + 头 4KB SHA-1 抽样等长篡改且伪造 mtime → 检出（触发重下）
≤32 KB（数千个小资源对象）length + mtime日常损坏（下载错误、磁盘坏块）必然改变二者之一
任意文件「强制完整校验」入口清空缓存全量重扫，兜底一切
已知取舍（文档化）

>32KB 文件在 4KB 之后的尾部等长篡改、且 mtime 被精确伪造——这种针对性攻击不在日常抽样覆盖内，由强制完整校验兜底。这与业界启动器的缓存策略一致；缓存文件本身在 %APPDATA%\SuyunCraft\verify-cache.json，schema 版本变化自动作废。

失效规则

变化结果
期望 SHA-1 / size 变化（如版本清单更新）键不同 → 自动完整校验
文件内容/长度/mtime 任一变化记录不匹配 → 完整校验 → 按结果重写记录
校验失败或文件缺失永不写入缓存
手动「🔍 强制完整校验」（设置页新按钮）缓存全清，下次启动全量
